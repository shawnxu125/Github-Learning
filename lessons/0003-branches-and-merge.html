03 · 分支：安全的平行宇宙

预计用时：40 分钟 · 前置：第 2 课 · 速查表：分支速查表

本课目标 理解分支到底是什么（其实便宜得惊人），并跑通 创建 → 开发 → 合并 的完整循环。

1. 分支是什么？

每个 commit 像一个存档点，串成一条历史链。分支就是一个可移动的路牌——一个指向某个 commit 的指针。创建分支不是复制整个项目，只是立一块新牌子，所以瞬间完成、几乎零成本。

          开发中...
         ↙
A ── B ── C  ← main（路牌）
     └── D ── E  ← feature-login（另一块路牌）

为什么要用分支？因为 main 应该永远是"能跑的干净版本"。新功能在分支上做，做砸了直接删分支，main 毫发无损——这就是"安全的平行宇宙"。

2. 核心命令

我想…命令
看所有分支（* 号是我在哪）git branch
创建并切换到新分支git switch -c feature-login
切回 maingit switch main
把分支的成果合并进 maingit switch main 然后 git merge feature-login
删除已合并的分支git branch -d feature-login
习惯 固定套路：切分支 → 小步提交 → 切回 main → merge → 删分支。旧教程里的 git checkout 也能干这些活，但新命令 switch（切分支）/ restore（恢复文件）分工更清晰，建议直接用新的。

3. 合并时发生什么

  • 快进合并（fast-forward）：如果 main 在你开发期间没动过，Git 只需把 main 的牌子往前挪——没有新 commit，无脑顺利。
  • 三方合并（merge commit）：如果两边都有新提交，Git 自动生成一个"合并提交"，把两条历史拧成一股。只要两边改的不是同一行，Git 自动搞定。
  • 两边改了同一行？那就是冲突——下一课专门讲。

4. 动手任务

  1. git switch -c feature-first，确认提示已切换；git branch 看两个分支。
  2. 在分支上新建一个文件 notes.md，写点东西，add + commit（用第 2 课的规范格式）。
  3. git switch main——注意 notes.md 神奇地"消失"了（它只在分支上）。这就是平行宇宙。
  4. git merge feature-first——文件回来了。运行 git log --oneline 看历史。
  5. git branch -d feature-first 删掉分支，然后 push。
  6. 🎮 通关 Learn Git Branching 的"介绍分支"前两关（5 分钟，强烈推荐，可视化建立直觉）。
