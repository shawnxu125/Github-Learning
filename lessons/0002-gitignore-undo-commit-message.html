02 · 日常安全网：.gitignore、撤销、提交信息

预计用时：40 分钟 · 前置：第 1 课 · 速查表：撤销速查表

本课目标 学会三件每天都会用到的事：让 Git 忽略不该管的文件、安全地撤销各级操作、写出半年后还能看懂的提交信息。

1. .gitignore：告诉 Git "别管这些文件"

项目里总有一堆不该进版本库的东西：依赖目录（node_modules/）、编译产物、密钥文件、系统垃圾（.DS_Store）。把它们提交进去会污染历史，甚至泄露密码。

在项目根目录建一个 .gitignore 文本文件，每行一条规则：

# 依赖和构建产物
node_modules/
dist/
*.log

# 密钥 —— 永远不要提交！
.env
secrets.json
注意 .gitignore 只对还没被跟踪的文件生效。如果某个文件已经提交过，要用 git rm --cached 文件名 让 Git 停止跟踪它（文件本身保留在磁盘上）。

懒人福利：gitignore.io 输入你的语言/框架，自动生成完整的 .gitignore。

2. 撤销三连：改乱了怎么办

撤销的位置取决于改动走到了哪个区域（回忆第 1 课的四个区域）：

情况命令效果
工作区改乱了，想恢复成上次提交的样子git restore 文件名丢弃 ① 的改动（不可找回）
已经 add 了，但不想提交这个文件git restore --staged 文件名从 ② 退回 ①，改动还在
刚 commit 就发现漏了文件 / 信息写错git commit --amend修改最新一次提交
安全边界 --amend（以及后面会学的 reset）只用于还没 push 到 GitHub 的提交。已经 push 出去的提交不要改写，这是 Git 社交礼仪的第一条。

3. 写好 commit 信息

commit 信息是给半年后的你（和未来的合作者）看的。推荐开源社区通用的轻量格式：

feat: 添加用户登录页面
fix: 修复计算器除零崩溃
docs: 补充安装说明
style: 调整首页配色

规则很简单：类型: 一句话说清做了什么。常用类型只有 4 个：feat（新功能）、fix（修 bug）、docs（文档）、style/refactor/chore（其他杂项）。第一行不超过 50 个字，用动词开头。

4. 动手任务

  1. 检查你的项目：有没有 .gitignore？没有就建一个（用 gitignore.io 生成），至少包含日志、依赖目录、.env。
  2. 制造一次撤销：随便改一个已跟踪文件 20 行，git status 确认它是橙色，然后 git restore 该文件——看改动瞬间消失。
  3. 再改一次，git add 它，然后 git restore --staged 它——观察 status 里从绿变橙，但改动还在。
  4. 用规范格式做一次真实提交：git commit -m "docs: 添加 .gitignore 忽略规则"，然后 push。
  5. 故意把某次 commit 信息写错，用 git commit --amend -m "正确的信息" 修正（趁还没 push）。

5. 本课推荐精读

📖 Pro Git 2.2 提交到仓库（含 .gitignore 正式说明）。提交信息规范可参考 Conventional Commits 中文（第 9 课 CI 会自动利用这个格式）。
