06 · 效率三件套：stash / amend / cherry-pick

预计用时：40 分钟 · 前置：第 3 课 · 速查表：撤销速查表

本课目标 掌握三个高频场景的优雅解法：中途被打断要切分支、刚提交就后悔、只想要别人那一个提交。

1. stash：临时挂起墙

场景：你在 feature 分支写了一半（还没 commit），突然要切到 main 改个急事。未提交的改动会跟着你跳来跳去，很烦。git stash 把当前所有未提交改动收进一个抽屉，工作区瞬间干净，切完分支回来再 git stash pop 取回：

git stash          # 改动收进抽屉，工作区变干净
git switch main    # 干净地切走办事
# ...办完事...
git switch feature-x
git stash pop      # 改动取回，抽屉清空

git stash list     # 抽屉里存了几层（可以存多次）

2. amend：修改刚拍的照片

第 2 课学过：git commit --amend 重写最新一次提交。补充一个组合技——漏了文件时：

git add 漏掉的文件
git commit --amend --no-edit   # 把文件补进上一次提交，信息不变
红线 amend 本质是"毁掉旧提交、造一个新提交"。只准用于没 push 过的提交。已 push 的改写会让协作者的历史错乱（单人项目偶尔违规后果也自负，养成习惯最重要）。

3. cherry-pick：只摘那一颗樱桃

merge 是"把整条分支倒进来"，cherry-pick 是"只要那一个提交"。场景：main 上有个 bug 修复提交，你想把它也放到 release 分支上，但不想合并 main 的其他半成品：

git log --oneline        # 找到那个提交的编号，如 a1b2c3d
git switch release
git cherry-pick a1b2c3d  # 复制那个提交的改动，在当前分支生成新提交

cherry-pick 遇到冲突的处理方式和 merge 完全一样：改文件 → add → git cherry-pick --continue。

4. 动手任务

  1. stash 演练：改一个文件不 commit → git stash → 确认 git status 干净 → git stash pop 取回。
  2. amend 演练：提交时故意漏掉一个文件，用 add + commit --amend --no-edit 补救，用 git log --stat -1 确认文件已并入。
  3. cherry-pick 演练：建分支 feature-pick，做一次小提交；切回 main，git cherry-pick <编号> 把它摘过来（如果内容相同可能提示空提交，属正常，说明机制生效了）。
  4. 收尾 push。
