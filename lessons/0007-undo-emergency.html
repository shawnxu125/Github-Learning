07 · 撤销事故：reset vs revert

预计用时：40 分钟 · 前置：第 2 课 · 速查表：撤销速查表

本课目标 掌握两个最强大也最危险的撤销命令，并记住一条保命法则：本地用 reset，已推送用 revert。

1. reset：时光机（仅限本地）

git reset 把当前分支的指针挪回过去的某个提交。三种模式的区别在于"工作区和暂存区的文件要不要跟着变"：

模式命令提交记录改动内容
mixed（默认）git reset HEAD~1撤销提交改动保留在暂存区外，文件不动 ✅安全
softgit reset --soft HEAD~1撤销提交改动保留在暂存区，可直接重新 commit
hard ⚠️git reset --hard HEAD~1撤销提交改动直接蒸发，不可找回

HEAD~1 表示"往回 1 个提交"，HEAD~3 是往回 3 个，也可以写具体提交编号。

保命法则 已经 push 到 GitHub 的提交，不要用 reset 改写。改写后本地和远程历史分叉，push 会被拒绝，强推（--force）会毁掉别人的工作。已推送的提交用下面的 revert。

2. revert：用"反向提交"抵消

git revert <编号> 不是删除历史，而是新增一个提交，内容恰好是目标提交的镜像反面（加的变成删的，删的变成加的）。历史像append-only 的账本，错误被公开纠正而不是抹掉——这正是团队协作欢迎它的原因。

git log --oneline        # 找到想撤销的提交，如 a1b2c3d
git revert a1b2c3d       # 生成一个"反着来"的新提交
git push                 # 正常推送，不需要任何强推

3. 决策流程图

想撤销什么？
├─ 没 add 的文件改动     → git restore 文件
├─ 已 add 未 commit      → git restore --staged 文件
├─ 刚 commit 就发现错了   → git commit --amend（没 push 时）
├─ 撤销本地最近几个提交   → git reset（没 push 时）
└─ 撤销已 push 的提交     → git revert 编号   ← 唯一安全答案

4. 动手任务（在安全沙盒里练）

  1. 建沙盒：mkdir ~/git-sandbox && cd ~/git-sandbox && git init。在里面连续做 3 个小提交（改文件→add→commit，重复三次）。
  2. git log --oneline 记熟历史，然后 git reset HEAD~1——看提交消失但文件内容还在（mixed 的安全性）。
  3. git commit -m "重新提交" 恢复，再试 git reset --hard HEAD~1——这次 git status 干干净净，改动没了。感受 hard 的威力。
  4. 救命彩蛋：git reflog——Git 偷偷记录了所有历史动作，找到刚才被 hard reset 掉的编号，git reset --hard <那个编号> 复活它。这是 Git 的后悔药本药。
  5. 做一次 git revert HEAD，观察历史：旧提交还在，上面多了一个反向提交。
