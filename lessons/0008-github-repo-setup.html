08 · 把项目打造成像样的开源仓库

预计用时：40 分钟 · 前置：第 5 课

本课目标 让仓库从"代码堆"变成"门面"：README、LICENSE、版本标签（tag）与 Release——这也是 CI/CD 的第一块地基。

1. 开源仓库三件套

文件作用怎么建
README.md项目门面：是什么、为什么、怎么装、怎么用自己写，GitHub 自动显示在首页
LICENSE授权协议，决定别人能不能/怎么用你的代码GitHub 建仓时勾选，或 choosealicense.com 三问选择
.gitignore忽略规则（第 2 课已做）✅

LICENSE 不知道选什么：想"随便用别找我麻烦"选 MIT，想"别人用了必须开源"选 GPL。个人项目 MIT 最常见。

2. tag：给历史钉上里程碑

commit 编号（a1b2c3d）没法向用户交代"哪个版本稳定"。tag 就是给某个 commit 钉一块永久名牌，惯例用版本号：

git tag -a v1.0.0 -m "第一个正式发布版本"   # 给当前提交打标签
git push origin v1.0.0                     # tag 不会随 push 自动上传，要单独推！
git tag                                        # 查看所有 tag
易错点 git push 默认不带 tag。忘了 push origin v1.0.0 是新手最常见的"我明明打了标签 GitHub 上怎么没有"。

3. GitHub Release：面向人类的发布页

tag 是 Git 层的标记，Release 是 GitHub 网页层的"发布会"：基于 tag 生成，可以写更新日志、挂安装包。路径：仓库页 → Releases → Draft a new release → 选你的 tag → 写说明 → Publish。

记住分工：tag 在 Git 里打，Release 在网页上发布。以后第 10 课我们会让 GitHub Actions 自动做这件事。

4. 动手任务

  1. 给你的项目补齐 README.md：项目名、一句话简介、如何运行。写得烂没关系，先有。
  2. 没有 LICENSE 就加一个（推荐 MIT）。
  3. 打第一个版本标签：git tag -a v0.1.0 -m "首个里程碑"，然后 git push origin v0.1.0。
  4. 去 GitHub 网页基于 v0.1.0 发布第一个 Release。
  5. 截图或记住这个页面——第 10 课结束时，它将由 GitHub Actions 自动发布。

5. 本课推荐精读

📖 GitHub Docs: About Releases + Choose an License（三分钟选对协议）。tag 原理见 Pro Git 2.6 打标签。
