10 · 实战：自动测试 + 自动部署

预计用时：50 分钟 · 前置：第 9 课 · 速查表：Actions 速查表

本课目标 搭一条真正的流水线：push → 自动构建/测试 → 自动部署上线。完成后你的项目实现全自动发布。
开工前告诉我 你的项目是什么类型？（静态网页 / Node.js / Python / 其他）下面有对应路线，选一条走即可。

1. 路线 A：静态网站 / 文档 → GitHub Pages（最简单，强烈推荐先走通）

GitHub Pages 免费托管静态站点，且官方提供了现成部署 Action。任何项目（React/Vue 构建产物、纯 HTML、文档站）都适用：

name: 构建并部署到 Pages
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    steps:
      - uses: actions/checkout@v4
      # 如果是纯 HTML 项目，跳过构建，直接发布整个目录：
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .          # 有构建产物就写 dist/ 或 build/
      - uses: actions/deploy-pages@v4

然后在仓库 Settings → Pages 把 Source 设为 GitHub Actions。push 后访问 https://你的用户名.github.io/仓库名/——你的代码上线了。

2. 路线 B：Node.js 项目 → 自动安装依赖 + 测试

name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm test        # 没有测试就先跑 npm run build 验证能构建

3. 路线 C：Python 项目

name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest           # 或 python 你的主程序.py 做冒烟测试

4. Secrets：密码不要写在 yml 里

部署要用的密钥（服务器密码、API key、token）放进 GitHub 仓库 Settings → Secrets and variables → Actions → New repository secret，yml 里这样引用，公开仓库也安全：

- name: 部署
  run: ./deploy.sh
  env:
    DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}
有自己的服务器？ 服务器部署的常见做法：Actions 通过 SSH 登录你的服务器执行 git pull && 重启服务（用 appleboy/ssh-action + SSH secret）。有这个需求告诉我，我给你出定制版任务。

5. 加分项：打 tag 自动发 Release

回忆第 8 课手动发 Release 的活儿，交给机器人——在任意流水线里加：

on:
  push:
    tags: ["v*"]        # 只在推 v 开头的 tag 时触发

# jobs 里加一步：
- uses: softprops/action-gh-release@v2   # 自动创建 Release

从此发布流程 = git tag v1.1.0 && git push origin v1.1.0，两条命令，测试、发布全部自动。

6. 动手任务

  1. 按你的项目路线（A/B/C）写好 workflow 文件，push，让 CI 变绿。
  2. 路线 A：打开你的 username.github.io 页面截图🎉 / 路线 B、C：故意写坏代码让测试变红，再修绿。
  3. 加一个 secret（随便起名叫 DEMO_SECRET，值写今天的日期），在 step 里 echo 引用它（日志里应显示 *** 而不是明文——这正是它在保护你）。
  4. （可选）加上 tag 自动 Release，打 v0.2.0 试试全自动发布。
