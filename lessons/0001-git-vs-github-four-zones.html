01 · Git 和 GitHub 到底是什么关系？

预计用时：40-50 分钟 · 前置：用过 clone 和 commit · 配套速查表：四个区域速查表

本课目标 学完这课，你能说清 Git 是什么、会初始化一个仓库，画出 Git 数据流动的完整地图，并解释：为什么我 commit 了，GitHub 上却没有？

1. Git 到底是什么？

Git 是一个版本控制系统：一个装在你电脑上的程序，负责给项目文件夹"存档 + 读档"。

  • 存档：每执行一次 git commit，Git 就把整个项目当时的样子拍一张快照，连同时间、作者、你写的说明一起存起来。
  • 读档：任何时候都能回到任何一张快照——改坏了、删错了、想看看上周的样子，都是一条命令的事。
  • 分布式：历史不锁在中心服务器上，每个使用者手里都有完整一份。这也是为什么 clone 下来的项目断网也能查历史。

可以把它理解成游戏存档：commit = 手动存档（还要写存档名），git log = 存档列表，后面要学的 reset / revert = 读档。Git 的存档特别省空间——每张快照只额外记录"和上一张相比变了什么"。

2. 怎么让 Git 接管一个项目：git init

Git 不会自动盯着你电脑上的任何文件夹。只有你明确初始化过的文件夹，Git 才会管理。初始化只有一条命令：

git init

它做的事情只有一件：在这个文件夹里创建一个隐藏的 .git 目录。这个 .git 目录就是仓库本身——所有快照历史、分支信息、配置全部装在它里面。把它删掉，你的文件还在，但全部历史消失，文件夹立刻退回"普通文件夹"。

对比没初始化已初始化（git init 之后）
文件夹里只有你的文件多一个隐藏的 .git 目录（= 仓库）
git status报错 fatal: not a git repository正常显示当前状态
git commit不可用可用，历史开始累积
误删文件找不回来只要之前 commit 过就能恢复
你的项目属于哪种？ 你的项目是 git clone 下来的，所以已经初始化过了——clone = 自动 init + 把完整历史复制下来。以后自己从零开新仓库（第 8 课会做）才需要手动 git init。

3. 一个最常见的误解

很多人以为 Git 就是"把代码存到 GitHub"。错。这是两个完全不同的东西：

  • Git：一个装在你电脑上的程序，给你的项目拍"快照"，历史全部存在本地。断网也能用。
  • GitHub：一个网站，托管 Git 仓库的副本，用来备份、分享、协作。它只是众多托管网站之一（还有 GitLab、Gitee）。

你之前 git clone 时，其实是把 GitHub 上的完整历史复制了一份到本地——之后你的 commit 都发生在自己电脑上，GitHub 一无所知，直到你 push。

一句话 Git 是相机 + 本地相册，GitHub 是网盘。你先在本地拍照存档，主动上传后网盘才有。

4. 核心心智模型：四个区域

Git 的所有操作，都是在下面四个区域之间搬运文件。这是整个 Git 的地图，后面所有课程都建在这张图上：

① 工作区 你实际编辑的文件，就是项目文件夹本身
→git add
② 暂存区 "下次要拍快照的改动"清单
→git commit
③ 本地仓库 已保存的快照历史，在你电脑上
→git push
④ 远程仓库 GitHub 上的那份副本

← git pull 把 ④ 的最新版本拉回本地 · git checkout/restore 从 ③ 恢复文件到 ①

为什么中间要插一个"暂存区"？因为它让你挑选：改了 10 个文件，可以只把其中 3 个打包成一次提交。这是 Git 和"整个文件夹备份"的本质区别——它管理的是你精心组织的变更，不是文件本身。

注意 git status 的输出：它会直接告诉你哪些文件在哪个区域——橙色 = 工作区改了但没 add，绿色 = 已 add 等待 commit。读 status 是 Git 用户的第一生存技能。

6. 动手任务

环境准备 在 VSCode 中打开你的项目，按 Ctrl + `（反引号）打开内置终端。后面所有课程都在这个终端里进行。
实验 A：初始化 vs 没初始化（3 分钟） 先在一个临时文件夹里亲眼看看两者的区别： 
mkdir git-demo && cd git-demo
# 先试试：git status —— 报错 not a git repository（没初始化）
git init
# 再试：git status —— 正常了，On branch main
ls -a
# 现在能看到隐藏的 .git 目录了——它就是仓库本身
看完可以删掉：cd .. && rm -rf git-demo（历史都在 .git 里，删了不留痕迹）。

任务 B：完整闭环（在你的真实项目里做，它是 clone 来的，已初始化）

  1. 运行 git status，读出结果：有橙色文件吗？有绿色文件吗？当前在哪个分支？
  2. 随便改一个文件里的几个字，再运行 git status——观察它从"看不见"变成橙色（工作区）。
  3. git add <那个文件>，再 git status——它变绿了（进入暂存区 ②）。
  4. git commit -m "练习第一次命令行提交"——快照进入本地仓库 ③。
  5. git log --oneline -5——看到你的新快照在最上面。
  6. git push——现在去 GitHub 网页上刷新，亲眼看到你的提交出现在网上。③→④ 闭环完成。
如果 push 报错 常见原因是认证问题（要求登录 GitHub）。这很正常，把报错信息贴回来问我，我们下次课也可以专门讲认证设置。
