09 · CI/CD 概念与第一个 GitHub Actions

预计用时：45 分钟 · 前置：第 5 课 · 速查表：Actions 速查表

本课目标 理解 CI/CD 到底解决什么问题，写出你的第一个 workflow 文件，让 GitHub 在你每次 push 后自动替你"验货"。

1. CI/CD 是什么（30 秒版）

  • CI 持续集成：每次 push 后，一台云端机器自动帮你构建 + 测试，立刻告诉你这次提交有没有搞坏东西。→ 解决"在我电脑上明明能跑"的问题。
  • CD 持续部署：测试通过后，自动发布/部署（上线网站、发 Release、推镜像）。→ 解决"手动发布又慢又容易漏步骤"的问题。

对你的个人项目意味着：你 push，机器人验货，验完自动发布。你只负责写代码。

2. GitHub Actions 核心概念（四个词）

GitHub Actions 是 GitHub 自带的免费 CI/CD 系统（个人公开仓库免费额度非常充裕）。四个词就能读懂它：

词含义类比
workflow一个自动化流程，= .github/workflows/ 下的一个 yml 文件剧本
trigger 触发什么时候开演：on: push / pull_request / workflow_dispatch…开演通知
job 任务一台云端虚拟机上跑的一大块活（如 build、test）一个剧组
step 步骤剧组里的一条条具体指令（checkout 代码、装环境、跑命令）一句台词

3. 解剖第一个 workflow

把这段保存到项目的 .github/workflows/hello.yml，push 后去仓库的 Actions 标签页看它跑：

name: 我的第一个流水线          # 显示在 Actions 页面的名字

on: [push]                    # 触发条件：任何 push

jobs:
  check:                       # job id
    runs-on: ubuntu-latest      # 用 GitHub 免费的 Ubuntu 虚拟机
    steps:
      - name: 领取代码
        uses: actions/checkout@v4        # 官方动作：把仓库 clone 到虚拟机
      - name: 打个招呼
        run: echo "你好，CI！"
      - name: 看看仓库里有什么
        run: ls -la

两个关键动作类型：uses: = 复用别人写好的动作（Action）（如 checkout）；run: = 直接在虚拟机里执行 shell 命令。整个 Actions 就是这两样东西的乐高。

去哪看结果 仓库网页 → Actions 标签 → 点进最新运行记录，能看到每一步的实时日志，绿✔红✘一目了然。失败了点进去看红色那步的日志即可。

4. 动手任务

  1. 在 VSCode 里创建 .github/workflows/hello.yml，粘贴上面的示例，commit + push。
  2. 打开仓库 → Actions 标签页，围观流水线自动运行，点开看每一步日志。
  3. 改造它：加一个 step run: git log --oneline -5，push，确认新 step 出现在日志里。
  4. 故意制造失败：把某个 run 改成 run: exit 1，push，观察红色 ✘ 和页面通知邮件。学会看失败日志比成功更重要。
  5. 修好它，让流水线重新变绿。
下一步预告 hello 只是玩具。下一课我们会根据你的真实项目类型（网页？Node？Python？）配置真正的自动测试，再做自动部署。做完这课告诉我你的项目是什么技术栈。
