11 · 毕业项目：完整开源发布流程

预计用时：60 分钟 · 前置：第 1-10 课全部内容

毕业考核 不查任何资料，独立走完一个真实功能的"开发 → 合并 → 发布 → 部署"全流程。卡住了允许查速查表，但每一步都要能说出"为什么"。

毕业任务清单

  1. 开分支：为你的项目想一个小新功能（改个页面文案、加个说明段落都算），git switch -c feature-graduation。
  2. 规范提交：在分支上完成功能，用 feat: ... 格式提交至少 2 次。
  3. 合并：切回 main，merge 分支（如遇冲突，独立解决）。删除已合并分支。
  4. CI 验证：push，去 Actions 页面确认流水线全绿。
  5. 发布：打 tag v1.0.0 并推送，触发自动 Release（或手动发布一次）。
  6. CD 验证：确认部署产物已更新（Pages 页面能看到你的新功能）。
  7. 事故演习：在沙盒目录里演示——"撤销一个已 push 的提交"该用什么命令？说给教练听你的推理（答案在撤销速查表底部，先自己答）。

进阶路线（毕业后的方向，随时找我开课）

  • Pull Request 工作流：即使单人项目也用 PR 合并（GitHub 网页上点按钮合并），这是开源协作的标准姿势。
  • rebase 与历史美化：git rebase -i 整理提交历史（先通关 Learn Git Branching 的 rebase 章节）。
  • fork + upstream：给别人的开源项目提第一个 PR。
  • Actions 进阶：矩阵测试、缓存、定时任务、多环境部署。
社区 毕业后建议加入 GitHub Community 或 r/git，真实项目里遇到的问题在那里都能找到同类。第一次帮别人解答 Git 问题的那天，你的存储强度就真正成型了。
