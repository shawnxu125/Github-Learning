05 · 远程仓库与 GitHub 认证

预计用时：40 分钟 · 前置：第 1 课

本课目标 搞懂 origin 是什么、push/pull 到底在跟谁说话，并一劳永逸解决"每次 push 都要登录"的认证问题（配 SSH 密钥）。

1. origin：给远程仓库起的小名

Git 不会记住"GitHub 上那个网址"，它把网址登记为一个别名，默认叫 origin。所以 git push origin main 的完整含义是："把 main 分支的提交，推送到别名为 origin 的那个网址"。

git remote -v          # 查看别名 → 网址的对照表
# origin  https://github.com/你/项目.git (fetch)
# origin  https://github.com/你/项目.git (push)

clone 过的仓库会自动登记好 origin。如果某个本地文件夹是 git init 新建的，需要手动关联：

git remote add origin https://github.com/你的用户名/仓库名.git

2. push -u 是干嘛的

第一次推送用 git push -u origin main。-u（upstream）建立"本地 main ↔ origin/main"的绑定，之后只需敲 git push / git pull，Git 知道该去哪。

3. 认证：SSH 密钥，配一次管所有项目

用 HTTPS 地址的仓库 push 时要求验证身份。GitHub 已不支持账号密码，要么用 Personal Access Token（会过期），要么——推荐——SSH 密钥：你电脑上生成一对钥匙，公钥交给 GitHub，之后 push 永远免密。

# 1. 生成密钥（一路回车，密码留空即可）
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 2. 复制公钥内容
cat ~/.ssh/id_ed25519.pub

# 3. 粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key

# 4. 把仓库地址换成 SSH 形式
git remote set-url origin git@github.com:你的用户名/仓库名.git

# 5. 测试
ssh -T git@github.com   # 看到 "Hi! You've successfully authenticated" 即成功
两种地址 HTTPS 形如 https://github.com/用户/仓库.git，SSH 形如 git@github.com:用户/仓库.git。同一个仓库两种地址都有效，认证方式不同。

4. 动手任务

  1. git remote -v——看看你的项目 origin 是 HTTPS 还是 SSH 地址。
  2. 如果是 HTTPS 且 push 时总要认证：按上面第 3 节配好 SSH 密钥，ssh -T git@github.com 验证成功。
  3. 如果还没有 GitHub 仓库：去 github.com/new 建一个（名字随意，Public），然后 git remote add origin ... + git push -u origin main。
  4. 验证绑定：之后 push 不再需要任何 origin main 参数和登录操作，git push 两个单词搞定。

5. 本课推荐精读
